# 流式 Markdown 源码教学章节模板

> 用于扩展课程，不属于学习主线。项目独有机制可以增加专属章节。

## 写作原则

1. 先说明该项目在成本模型中负责哪一层；
2. 明确输入合同是累计全文、suffix 还是新增 chunk；
3. 正常路径之外，至少推演未闭语法、final 或 reset；
4. cache 必须说明 key、identity、失效与 eviction；
5. 性能结论优先转成可测计数，不引用无统一环境的排名；
6. 练习复刻核心机制，不复刻完整组件库。

**章节标题：第 N 章 项目名——核心机制**

## 本章要解决的问题

说明前一章留下的成本或状态问题。

## 本章目标

| 项目 | 内容 |
|---|---|
| 前置知识 | 优先引用前章 |
| 本章重点 | 1–3 个机制 |
| 第一遍重点 | 3–6 个源码入口 |
| 完成后应能回答 | 输入、状态、复用和 final 的核心问题 |

## 核心心智模型

用一张图或一个公式说明本次更新的完整路径。

## 正常路径与失效路径

- 正常追加；
- 未闭语法；
- final/static；
- 非前缀改写/reset；
- cache 或重组件失败。

## 关键源码与等价伪代码

固定到 commit，解释状态 owner 与 identity。

## 设计收益

说明减少了哪一层工作。

## 适用边界与常见误区

区分 parser、render、调度、安全和兼容。

## 本章练习

给出最小实现与故障注入。

### 练习验收

- 产物；
- 可观察结果；
- 失败条件。

## 检查理解

3–5 个要求从记忆解释机制的问题。

## 本章小结

压缩本章心智模型，并连接下一章。
