# Issue #5 Evidence-backed Learning Artifact Implementation Plan

> **For agentic workers:** Execute one task at a time. Begin each task with a focused failing test, keep every project-owned TypeScript field documented, obtain an independent review before its commit, and only check a step after its evidence passes.

**Goal:** Turn one already-frozen source excerpt into a structured `source_fact` Evidence Record and Claim, gate a deterministic Markdown draft on that evidence, bind user publication approval to the exact draft hash, Output Root identity, and canonical target identity, then atomically publish one Learning Artifact without overwriting different existing content.

**Architecture:** This stays a deliberately thin, one-shot success path rather than Issue #6's generic multi-turn loop. `readSource` first creates the private immutable Source Snapshot. A new runtime command may register evidence only from an existing successful `source_read_observed` fact; claims can cite only those registered Evidence IDs. The reducer derives Evidence/Claim state and verifies every relationship again during Journal replay. A deterministic renderer, not free-form model text, emits citation links from these structured identities. The runtime persists the draft artifact, pauses for an exact `PublicationApprovalBinding`, and only then calls a narrowly scoped same-directory atomic publisher.

**Tech Stack:** Node.js 24+ filesystem APIs, strict ESM TypeScript, Zod, `better-sqlite3`, Vitest, Node `crypto`, Mermaid.

## Non-goals and fixed boundaries

- Do not add `search_sources`, model-visible tools, automatic tool dispatch, a generic multi-turn Research Loop, retry/error taxonomy, live-model integration, CLI publication commands, or durable crash/effect reconciliation. Those belong to later tickets.
- A ScriptedModel fixture proves the completed happy path, but it must provide only a bounded typed artifact proposal; it must never author or select citation identities.
- The public target is a caller-provided local Markdown path under an explicitly configured canonical Output Root. It is not an Artifact Store object, and the Output Root must not overlap the private Runtime Home.
- The normal publish path is intentionally the only promised path: publication effects are not yet a recoverable durable operation. A crash after an external no-clobber publication attempt is documented as the #14 reconciliation boundary rather than silently inferred on restart.

Directly constructed events must not bypass these checks.

- [x] **Step 4: Implement publisher and runtime orchestration**

`LearningArtifactPublisher` accepts only a prepared canonical target binding and exact Markdown bytes. It rechecks parent identity, rejects symlink/non-file target conditions, creates a `0600` temporary file in the target directory with `O_EXCL|O_NOFOLLOW`, fsyncs it, then atomically hard-links it to an absent final name and removes the temporary file. Ordinary `rename` is deliberately avoided because portable Node rename overwrites existing targets. If the final regular file already has exactly the expected bytes, return idempotently; otherwise reject without overwrite. It must not create parent directories or follow a final symlink.

The runtime calls the publisher only after a durable exact user publication approval. It does not treat a writer crash as a completed effect: only a successful publish call may append `learning_artifact_published`. It maps conflict/IO details to safe named application errors and guards the append with `expectedLastSequence`.
